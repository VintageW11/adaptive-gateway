SAW VPN selection — formulas and weights

The gateway picks the VPN with the highest SAW score on the current traffic profile. That is the implementation in saw.py / app.py — nothing on the lab was changed.

Decision rule

For every enabled path i,

i* = arg maxi Si

A Fail mark multiplies that path’s score by 0.05 (tunnels stay up). Auto does not invent a fifth formula; it only chooses one of the four weight vectors below (Everyday browsing, Gaming & calls, Video streaming, Big downloads).

Metrics (same order as the weights)

Live values come from two ICMP pings to 8.8.8.8 on that tunnel. If the probe fails, the characteristic table is used instead.

SymbolMetricLive source
LLatency (ms)mean RTT
JJitter (ms)stdev of the two RTTs, capped at 5 ms
PLoss (%)ping loss
T Throughput index T = max(100 − 2P, 0.1) — not iperf / not Mbps
R Reorder (%) R = min(0.5P, 100)
M MOS M = clip(4.5 − L/150 − J/40 − P/25, 1, 4.5)
UMTU1400 if a DF ping of 1372 bytes succeeds; else table MTU

On a live sample, latency and jitter are floored so lab sub-ms pings cannot explode the inverse terms:

L ← max(L, 10), J ← max(J, 3)

Normalization (benefit form)

nL = 10 / max(L, 0.1)
nJ = 5 / max(J, 0.01)
nP = (100 − P) / 100
nT = T / 100
nR = (100 − R) / 100
nM = M / 5
nU = U / 1500

Lower L, J, P, R and higher T, M, U raise n.

SAW score

Weights w are normalized so Σ wk = 1.

S = Σk=17 nk wk  +  0.03 · (sec / 5)  +  0.03 · (rel / 5)  +  A

Protocol security/reliability (sec, rel) add at most 0.06. Affinity A is a capped tie-breaker, not a personality override:

A = min(0.02 · araw, 0.08)

So even Gaming’s WireGuard raw affinity 3.5 only adds 0.07. A clear live latency gap still wins.

Simulated failure:

Sfail = 0.05 S

Profile weights (what actually tips the scale)

Order: Latency, Jitter, Loss, Throughput, Reorder, MOS, MTU.

Profile (UI name)wWhat wins
Everyday browsing (balanced) 15, 15, 15, 15, 10, 20, 10 MOS + even QoS. Table/live both favor WireGuard, then IKEv2, SoftEther.
Gaming & calls (gaming) 35, 30, 10, 5, 5, 10, 5 Latency + jitter. WireGuard / Nebula / IKEv2. SSTP is almost excluded.
Video streaming (streaming) 5, 10, 35, 25, 5, 15, 5 Loss + throughput index. OpenVPN / SoftEther / IKEv2.
Big downloads (downloads) 5, 5, 10, 40, 5, 5, 30 Throughput index + MTU. SSTP / OpenConnect / OpenVPN.

Custom sliders are the same seven weights, renormalized to 100%.

That is why browsing/gaming usually land on WireGuard: lowest L and J, highest MOS, and those metrics carry most of the weight. Streaming/downloads can prefer TCP-ish paths because loss, T, and MTU outweigh latency. Fail does not change the formula; it only scales that path’s S down so the next-highest SAW score is selected.
